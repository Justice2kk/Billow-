# Changelog

## 2026-10-22 — Nidomo public identity

- Adopted **Nidomo** as the current public platform name across the public-facing docs, examples and compatibility descriptions.
- Documented **Nimo** as the mascot's current name and kept the project's previous names in the historical migration record.
- Adopted the owner-authorized clean break: current `nidomo://`, `@nidomo/*`, `org.nidomo.*`, `data-nidomo-*`, project and workspace identities; former Billow OS persistent data is not migrated.
- Updated the public compatibility registry, generated index and validator to the Nidomo contracts, while preserving historical project evidence.

## 2026-10-20 — Cielori rebrand

- renamed public-facing project text, guides and examples from BillowOS/Billow to Cielori;
- replaced the public README artwork with Cielori-branded art;
- retained existing technical routing and SDK identifiers where changing them would break compatibility;
- added a guide documenting the distinction between the new brand and existing technical names.


## 2026-10-20 — clearer compatibility

- added a checkbox-style compatibility overview with simple supported/experimental/unsupported indicators;
- linked it from the public homepage, documentation, web guide and first-time tour;
- kept the full generated index and source registry unchanged.


## 2026-10-20 — a friendlier front door

- redesigned the public README around what visitors actually want to make;
- added a repository banner, clearer navigation and an honest project-status summary;
- introduced beginner guides for websites and applications, plus a plain-English FAQ;
- simplified documentation discovery and the application/web entry points;
- clarified the difference between internally accepted Creator/Sites workflows and public runtime availability;
- kept the compatibility registry and private/public boundary unchanged.

## 2026-10-06 — public developer-platform foundation

- replaced the placeholder public skeleton with independently understandable platform documentation;
- aligned public authoring with HTML/CSS and TypeScript/JavaScript/Luau rather than legacy JML/JSS;
- added a machine-readable compatibility registry with explicit statuses and verification identifiers;
- generated the searchable compatibility index from that registry;
- added public-boundary/internal-link/registry validation and CI;
- added a truthful HTML/CSS source example without inventing an uncertified site manifest;
- converted old JML/JSS pages into explicit legacy pointers.
