# Questions you might have

### Is Nidomo a real operating system?

It's a **hosted operating environment inside Roblox**, not a replacement for Windows, macOS, Linux or your phone's OS. It has its own apps, files, windows and services, using Roblox as the host.

### Do I need to know code?

Not to explore the desktop or use everyday apps. To make a website or application, some HTML/CSS or programming knowledge helps—and the [starter pages](OVERVIEW.md) are designed to meet you where you are.

### Can I use normal HTML and CSS?

**A documented subset, yes.** Common structures, text, links, images and flex-based layouts are supported with limits. The [compatibility index](../compatibility/FEATURES.md) is more precise than a simple “yes.”

### Can I run my existing website unchanged?

Don't assume that. Nidomo doesn't support everything a browser does, and it has its own `nidomo://` routing, permission and publication rules. Begin with [the web guide](../web/README.md).

### What about JavaScript and TypeScript?

TypeScript is the default Nidomo creator-app language, with JavaScript and Luau alternatives. Web page scripting remains more restricted and feature-gated. Internal acceptance doesn't automatically imply a generally available public release.

### Is Nidomo already publicly playable?

This repository does **not** announce a public Roblox release. Check official Nidomo release channels for availability; internal testing and public distribution are different steps.

### Is this repository the entire Nidomo source code?

No. This is the **public developer and documentation surface**, not a mirror of the private engine implementation.

### Can I download Nidomo from this repo?

Not as a standalone operating system. The docs and examples are useful to explore, but they aren't a desktop installer.

### Can I freely reuse the code?

The [license file](../../LICENSE) currently does not grant a general reuse license. Public GitHub visibility alone does not make the private engine open source.

### I found an error or a confusing page. What now?

Start with the [contribution guide](../../CONTRIBUTING.md). Clear examples of what's wrong, expected behavior and affected documentation are much more useful than vague feature requests.
